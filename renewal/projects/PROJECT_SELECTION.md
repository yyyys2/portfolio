# 대표 프로젝트 선정

## 기준

기존 포트폴리오에서 본인의 역할과 구현 내용을 설명할 수 있고, 서로 다른 개발 역량을 보여 주는 네 프로젝트를 선정한다. Memomi는 사용자의 요청에 따라 포함한다. 시안에 표시된 프로젝트 이름이나 기술 스택만으로 대표 여부를 결정하지 않는다.

| 순서 | 프로젝트 | 선정 이유 |
| --- | --- | --- |
| 01 | AI Agent UI | 분석 조건, 다양한 응답 유형, Canvas 편집, 메일 발송 등 복잡한 업무 UI와 상태 흐름을 설명할 수 있다. |
| 02 | webOS 오버레이 앱 | 사용자 요청으로 스마트 디스플레이를 교체했다. 시청 흐름을 유지하는 오버레이 UX, 리모컨 포커스 복귀, 비동기 추천 데이터 처리 경험을 보여 준다. |
| 03 | 디지털 사이니지 | 대시보드·리스트 동기화, 조회·수정 흐름과 테이블 성능 개선 등 운영 중인 서비스의 개선 경험을 보여 준다. |
| 04 | Memomi | Windows 메모 앱과 Tauri·React 기반 데스크톱 구현으로 프로젝트의 제품·플랫폼 범위를 넓힌다. |

## 데이터 기준

- 대표 목록과 순서의 원본은 `src/data/selectedProjects.ts`다. Home과 Projects에서 함께 사용한다.
- AI Agent의 상세 개발 내용은 현재 `ProjectsView.tsx`에 정리된 분석 조건·채팅·Canvas·메일 등의 내용을 유지한다.
- webOS와 디지털 사이니지는 리뉴얼 이전 커밋 `bed3273`의 `src/data/projects.ts`에서 각각 `tv-overlay-shopping`, `digital-signage-management` 항목을 근거로 정리했다.
- 대표 webOS 오버레이 앱은 Svelte·TypeScript 기반의 TV 오버레이 쇼핑/푸드 추천 앱이다. React·Redux 기반의 스마트 디스플레이 서비스는 OTHER PROJECTS로 이동했으며 두 프로젝트의 내용을 섞지 않는다.
- Memomi는 기존 가이드에 확인되는 Windows 메모 앱, 빠른 기록·재진입, Tauri·React·TypeScript 범위로 설명한다. 배포 실적·사용자 수·정량 성과·추가 기능을 추정해서 넣지 않는다.
- SmartSolution API Portal은 기존 프로젝트와의 대응 근거가 없어 대표 목록에서 제외한다. 이름이 비슷한 에너지 B2B 포털과 임의로 같은 프로젝트로 취급하지 않는다.
- V2X, 모빌리티 홍보 사이트, 호스피탈리티 사이니지 등 나머지 기존 프로젝트는 OTHER PROJECTS에 유지한다. 대표 목록의 ID는 OTHER PROJECTS에서 자동으로 제외한다.

기존 시안 이미지의 이름과 이 문서가 다르면 최신 선정 결과와 실제 프로젝트 데이터를 기준으로 콘텐츠를 구현한다.
